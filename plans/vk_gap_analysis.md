# 3️⃣ ЧТО РЕАЛИЗОВАНО С ОШИБКАМИ ⚠️

## 3.1. КРИТИЧЕСКИЕ ОШИБКИ

### 🔴 ОШИБКА #1: Отсутствие загрузки файлов
**Проблема:** В ТГ есть 2 источника для минусовки/кавера:
1. [📂 Из моих треков] → выбор task_id
2. [📤 Загрузить файл] → upload audio → KaraokeStates/CoverStates.waiting_for_audio_upload

**В ВК:** Только вариант #1 (из БД), загрузки файлов НЕТ  
**Последствия:** Пользователи не могут сделать кавер/минусовку своего аудио

### 🔴 ОШИБКА #2: Нет проверки is_unlocked перед публикацией
**В ТГ:**
```python
cb: post_{task_id}:
    if not is_unlocked:
        return "❌ Сначала разблокируйте полную версию (1 токен)"
```

**В ВК:** Нет таблицы demo_tracks → нет проверки → не реализовано

### 🔴 ОШИБКА #3: Генерация в threading вместо Celery
**Проблема:** В VK-боте генерация запускается в `threading.Thread`:
```python
# main_vk.py:1246
thread = threading.Thread(target=generate_song_thread)
thread.start()
```

**В ТГ:** Используется Celery + RabbitMQ:
```python
task = generate_song_task.apply_async(user_id, lyrics, genre, custom_mode)
```

**Последствия:**
- ❌ Нет очереди задач
- ❌ Невозможно отследить статус
- ❌ При перезапуске бота потеряются все задачи
- ❌ Нет retry при ошибках

**Важность:** 🔥🔥🔥 КРИТИЧНО++

### 🔴 ОШИБКА #4: Списание токена ПОСЛЕ генерации
**В ТГ:**
```python
# ПРАВИЛЬНО: Списываем ДО генерации
balance -= 1
task = generate_song_task.apply_async(...)
```

**В ВК:**
```python
# НЕПРАВИЛЬНО: Списываем ПОСЛЕ генерации (в потоке)
thread = threading.Thread(target=generate_song_thread)
thread.start()
# ... внутри потока ...
execute_query_sync("UPDATE users SET balance = balance - 1 WHERE user_id = %s", (user_id,))
```

**Последствия:**
- ❌ Если генерация упадет, токен не вернется
- ❌ Пользователь может запустить несколько генераций параллельно

**Важность:** 🔥 КРИТИЧНО

### 🔴 ОШИБКА #5: Отсутствие уникального task_id
**В ТГ:**
```python
task_id = str(uuid.uuid4())
task = generate_song_task.apply_async(task_id=task_id, ...)
```

**В ВК:**
```python
# НЕПРАВИЛЬНО: task_id берется из результата генерации
result = generate_suno_song_sync(lyrics, style)
if result:
    audio_url, task_id, audio_id = result
```

**Последствия:**
- ❌ Невозможно отследить задачу до её завершения
- ❌ Нет записи в БД о старте генерации

**Важность:** 🔥 КРИТИЧНО

### 🔴 ОШИБКА #6: Несинхронная работа с FSM
**Проблема:** В VK-боте FSM сбрасывается ПЕРЕД отправкой задачи в поток:
```python
# main_vk.py:1343
self.reset_state(user_id)  # ← СБРОС ДО ЗАВЕРШЕНИЯ
thread = threading.Thread(target=generate_instrumental_thread)
thread.start()
```

**В ТГ:**
```python
task = generate_song_task.apply_async(...)
await state.finish()  # ← СБРОС ПОСЛЕ ОТПРАВКИ В CELERY
```

**Последствия:**
- ⚠️ Если пользователь нажмет кнопку сразу после старта генерации, состояние уже сброшено

**Важность:** ⚠️ СРЕДНЕ

## 4.4. СОСТОЯНИЯ FSM

### 📊 Архитектурное решение

**ТГ:** aiogram FSMContext (в памяти + Redis)  
**ВК:** Кастомный VKStateManager (Redis)

```python
# ТГ
await state.set_state(CreateSongStates.waiting_genre)
await state.update_data(lyrics=text)
data = await state.get_data()
await state.finish()

# ВК
asyncio.get_event_loop().run_until_complete(
    self.state_manager.set_state(user_id, States.WAITING_GENRE)
)
asyncio.get_event_loop().run_until_complete(
    self.state_manager.update_data(user_id, lyrics=text)
)
```

### 🔧 РЕШЕНИЕ: Обертки для упрощения

**Создать хелперы:**
```python
def set_state_sync(self, user_id, state):
    asyncio.get_event_loop().run_until_complete(
        self.state_manager.set_state(user_id, state)
    )

def update_data_sync(self, user_id, **kwargs):
    asyncio.get_event_loop().run_until_complete(
        self.state_manager.update_data(user_id, **kwargs)
    )
```

⚠️ **НЕ РЕАЛИЗОВАНО** (можно оптимизировать, но не критично)

## 4.5. LONGPOLL vs WEBHOOK

### 📊 Сравнение

**ТГ:** Webhook (instant delivery) или Long Polling  
**ВК:** Только Long Polling (BotLongPoll)

### 🔧 РЕШЕНИЕ

VK не поддерживает webhook для сообщений (только для Callback API групп).  
✅ **Используется VkBotLongPoll** — правильное решение для VK
